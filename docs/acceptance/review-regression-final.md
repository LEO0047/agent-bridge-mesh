# 共享稿件的樂觀版本控制

## 原則

樂觀版本控制允許雙方先各自編輯，提交時再檢查衝突。編輯者讀取稿件及版本，提交時附上該 base_version。伺服器以原子方式比對版本並寫入：相符才接受並遞增版本；不符則拒絕寫入，回報 STALE_VERSION。提交者須保留自己的修改，重讀最新版、判斷並整合差異，再以新讀取的版本重送，不能只換版本號而覆蓋他人修改。

## 限制

此機制只保護經過版本檢查的寫入；繞過檢查的修改不受保護。版本以整份稿件為單位，即使雙方改的是互不相干的段落，也一樣會判定為衝突。它不能自動解決語意衝突，也不保證文字正確；提交較晚不代表內容較好。被拒絕的修改不會自動納入稿件，若未保存並整合，仍可能遺失；頻繁衝突也可能導致反覆重試。

本協作流程的 APPROVE 僅對受審版本有效。任何改稿都使舊核准失效；整合後須重新驗證，雙方再對同一新版審核。
